# NASAQ AI V1.1 — إصلاحات آمنة جزئية

**هذه ليست نسخة منشورة أو معتمدة علميًا.** انتقل التطوير من `NASAQ-AI-V1.zip` الأصلي إلى فرع إصلاح مستقل.

## تم تنفيذه

1. `quranVerifier.ts`: فصل إثبات وجود الإحداثيات عن اعتماد نص الآية؛ عند غياب مدونة معتمدة يرجع `null` ويرفض التوثيق. لا نصوص بديلة مزعومة.
2. `quranApiService.ts`: منع استخدام جلب بيانات غير مدقق أو `localStorage` مصدرا للآيات؛ عرض رسالة «المصدر غير متاح» بدل ملء السورة بقوالب.
3. `tools/import-tanzil-corpus.mjs`: مستورد TSV/pipe `surah|ayah|text` مع بصمة SHA-256 مرجعية، واكتمال 114 سورة و6236 آية وترتيبها وعدم تكرارها؛ يحفظ النص كما ورد دون إعادة صياغته. يرفض الملفات الجزئية. `tools/verify-corpus.mjs` يفحص المحتوى المعبأ قبل التشغيل والبناء.
4. `apiMiddleware.ts`: API مغلق افتراضيًا؛ تحقق Firebase ID JWT وتوقيعه وشروطه، سقف جسم الطلب 12KB، نص حتى 4000 حرف، معدل أولي 10 طلبات /15 دقيقة /مستخدم، رسائل خطأ عامة؛ لا يعد هذا بديلًا عن بوابة إنتاج موزعة.
5. `researchStore.ts`: أبحاث المستخدم المصادق عليه في Firestore فقط؛ لا fallback إلى shared localStorage؛ تخزين ضيف مؤقت في sessionStorage؛ bookmarks ذات مفاتيح تتضمن صاحب الحساب؛ فصل حالة الواجهة عند تغيير المستخدم.
6. `firestore.rules`: منع تغيير `owner_id` في عمليات التحديث؛ **قواعد الإنتاج لم تُختبر في Emulator ولم تُنشر**.
7. تصحيح إحالات معجمية خاطئة (`12:87`, `84:14`, `6:82`) ووقف ادعاء تحقق الجذور والعدد، وتعطيل الاستنتاجات المحلية المبنية على نتائج جاهزة.
8. جعل اللغة الافتراضية `ar` ورفع شفافية حالة مزودي AI.

## تشغيل Windows (بعد تثبيت Node 22+)

```powershell
npm install
npm test
npm run verify:corpus
npm run lint
npm run build
npm run dev
```

**قد يبدأ موقع React لكن قسم المصحف والبحث الموثقين سيظلان مقفلين حتى اعتماد المدونة.** النشر التجريبي عبر `npm run build` ثم `npm start` يشغّل خادم Express مربوطًا بالمضيف المحلي `127.0.0.1` فقط. لم يُختبر هذا المسار تشغيلًا كاملًا في بيئة إنشاء هذه الحزمة لأن تنزيل التبعيات لم يكن متاحًا.

## استيراد النص الكامل (مهم)

1. نزّل نص **Tanzil Uthmani** الكامل من https://tanzil.net/download/ بصيغة `surah|ayah|text` إن توفرت؛ انتبه للترقيم والرسم والرواية والترخيص. راجع مصدرًا مستقلًا لضبط النسخة قبل الاعتماد.
2. حصل على **SHA-256 مرجعية مستقلة من مصدر موثوق**. لا تجعل الأداة تولد لنفسها بصمة وتعد ذلك تصديقًا للمحتوى.
3. بعد التحقق من المصدر والبصمة، نفذ:

```powershell
node tools/import-tanzil-corpus.mjs C:\path\to\quran-uthmani.txt TRUSTED_64_CHARACTER_SHA256
npm run verify:corpus
npm test
```

4. استعن بتحكيم نصي مستقل للآيات ومقارنة نسخة معتمدة (6236 آية)، واختبر بسملات السور والوقف وعلامات الرسم قبل وصف المدونة بأنها محققة. فحص البصمة والاكتمال **لا يكفي** للحكم بصحة القرآن بذاته.
5. لتوزيع نسخة من Tanzil، أظهر النسبة الواضحة للمصدر ورخصته CC BY 3.0 وأبق النص منقولًا دون تعديل وفق شروط Tanzil.

**الحالة حاليًا:** `src/data/approvedCorpus.json` فارغ عمدًا (0/6236). لن نملأه بنص غير موثوق أو باقٍ آلي. `src/data/verifiedVerses.ts` (43 آية موروثة من النسخة الأصلية) باقٍ للمراجعة التاريخية فقط، **وليس مصدرًا مخولًا لمنح ختم التوثيق**.

## الضوابط والقيود قبل الإنتاج

- إتمام Firebase Rules Emulator: مالك/غير مالك/تبديل owner، ونشر القواعد فقط بعد النجاح.
- `FIREBASE_PROJECT_ID` يجب أن يطابق مشروع التوثيق؛ احفظ `GEMINI_API_KEY` خارج المصادر؛ اترك `NASAQ_ENABLE_PUBLIC_API=false` حتى انتهاء التدقيق.
- حدود الطلبات داخل ذاكرة عملية واحدة وليست حصصًا موزعة؛ يقتضي الإنتاج Reverse Proxy وWAF ومعدل طلبات موزعًا وحد تكلفة وHTTPS ومراقبة.
- فحص تبعيات `npm audit`, التحقق من استدعاءات Gemini الحقيقية، واختبارات React/Chromium لم تكتمل، فلا تعتبر تلك البنود ناجحة.
- ترحيل بيانات guest المخزنة بمفاتيح `nasaq_saved_*` القديمة يجب أن يتم بمراجعة صريحة؛ لم نُظهرها آليًا لتفادي اختلاط الحسابات أو إعادتها دون صلاحية.
- جميع المحتويات التفسيرية والروابط والخرائط القديمة تحتاج تحكيمًا مستقلاً؛ هي ليست نتائج حوسبة موثقة للمدونة كاملة.
