# NASAQ AI V1.2 — تعليمات الاستلام

هذا فرع إصلاح/بحث أولي للمنصة القرآنية. **لا يعتبر منصة موثقة للتفسير أو جاهزة للنشر العام**.

## ما الذي تغير؟
- استرجاع أدلة من القرآن الموثق بدلاً من ترك Gemini يختار مراجع حرة من ذاكرته.
- دعم مفاتيح الآيات وأسماء السور مع الأرقام الغربية/العربية في تحديد المراجع.
- تقييد الاستشهادات بمجموعة الأدلة المسترجعة، وإكمال التحقق منها عبر المحقق المحلي.
- إصلاح استيراد Firebase Auth في واجهتي البحث ونقض الفرضية؛ عرض الأخطاء بدل إخفائها.
- إزالة النسب الوهمية لتقدم البحث، وتحذير عن حدود الاستنتاج الآلي.
- إظهار مصدر Tanzil ورخصة النص في التذييل.

## التشغيل بعد نقل المشروع إلى بيئة متصلة بالإنترنت

```sh
npm install
npm test
npm run verify:corpus
npm run lint
npm run build
npm run dev
```

إذا فشل أي من هذه الأوامر، لا تعلن أن الموقع جاهز. لاحظ أن `npm run verify:corpus` في هذه الحزمة يعرض `NOT INSTALLED`، وهذه نتيجة تحذيرية متوقعة وليست إثبات اكتمال الآيات.

### كيف تثبت قاعدة القرآن؟

1. ادخل https://tanzil.net/pub/download/index.php ؛ اختر Uthmani وملف TXT يحتوي على أرقام السور والآيات، واحتفظ بخيارات التصدير والملف الأصلي دون تغيير حرف واحد.
2. احصل على بصمة SHA-256 *من قناة مستقلة موثوقة*، ولا تستخدم البصمة الناتجة محليًا باعتبارها إثباتًا مستقلًا للمصدر.
3. شغّل:

```sh
node tools/import-tanzil-corpus.mjs ./quran-uthmani.txt <TRUSTED_64_HEX_SHA256>
npm run verify:corpus
```

4. قارن المحتوى مع مرجع ثانٍ موثوق، وتأكد من توافق الرواية وترقيم الآيات والبسملات وعلامات الرسم. سلامة البصمة تثبت عدم تغير البايتات عن نسخة معينة؛ **لا تثبت بذاتها صحة نسبة النص للمصدر**.
5. بعد توثيق ذلك، أجرِ اختبارات Firebase والصلاحيات ومتطلبات الخصوصية والـ API قبل تفعيل `NASAQ_ENABLE_PUBLIC_API=true`.

### الإعدادات

انظر `.env.example`: `GEMINI_API_KEY` (على الخادم فقط)، `NASAQ_GEMINI_MODEL`، `FIREBASE_PROJECT_ID`، `NASAQ_ENABLE_PUBLIC_API` (معطل افتراضيًا).
